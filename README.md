# AutoDroid 0.4.0

普通手机短信警告自动化应用，Android 8.0（API 26）以上，无需 root。

## 使用

当前版本使用收件箱 ContentObserver 自动触发，可处理标准收件箱中可读的 SMS/RCS；小米应用通知监听仍禁用。

1. 覆盖安装 APK 并打开一次应用，现有双来源/通知宏会转换为普通 SMS 宏；无号码的宏自动禁用，需补充号码再启用。
2. 在“权限与后台设置”授权读取短信、接收短信、通知和悬浮窗；读取短信用于数据库自动触发，按需授予勿扰访问。
3. 新建或编辑宏，通过通讯录多选或手填多个发送号码，设置关键词、音量、音源和弹窗。
4. 保存后可手动测试，再开启后台短信监听，用普通 SMS 验证。
5. 主界面从最近任务隐藏，桌面入口与服务通知仍可使用。

音源可选系统铃声或通过系统文件选择器选择本地音频，默认系统闹钟铃声。
音量支持闹钟、媒体、铃声、通知；设置百分比转换为设备实际档位，播放使用同一通道。
声音循环播放，点击确认或达到时限（5～600 秒）停止。音量不自动恢复。
规则、启用状态和日志保存于应用私有目录，重启后保留。短信和音频不上传，无网络权限。

## 匹配与执行

- 一条宏支持多个发送号码，任意一个匹配即可触发，支持换行、中英文逗号/分号分隔；
- 完整发送号码匹配；统一全角/半角及数字格式，去除空白、不可见方向字符、括号和连字符，兼容中国 `+86` 和 `0086` 前缀。
- 通讯录列表支持姓名/号码搜索及多选；可混合使用手填号码和联系人号码。
- 保存的是选中时的号码，不随通讯录后续修改自动同步；选择结果在保存宏后生效。
- 兼容旧版单号码规则，编辑保存后使用多号码格式。
- 关键词区分大小写，留空匹配所选号码所有短信；分段短信合并匹配。
- 多条规则命中按列表顺序执行，最后一条接管声音和弹窗；日志记录每次执行。
- 日志包含宏名称、收到短信的脱敏号码及未命中原因，不保存短信正文或完整号码。日志最多约 16000 字符。
- 新警告替换当前警告，不进行排队。关闭监听同时停止当前警告。

## 权限和系统限制

接收广播使用 RECEIVE_SMS，不发送短信。READ_SMS 用于监听开启后的新增收件箱查询和用户主动诊断。
通讯录 READ_CONTACTS 权限仅在使用联系人选择时申请；拒绝后仍可手动输入号码。
只读取联系人姓名和号码供选择，不上传通讯录、不修改联系人。
当前版本不使用通知访问权限。之前已授权的通知监听服务已在组件配置中禁用。
Android 13+ 申请通知权限。悬浮窗和勿扰访问需在系统设置中明确授权。
以前台 specialUse 服务执行用户开启的短信自动化，播放时增加 mediaPlayback 类型。
播放期间使用音频焦点及局部唤醒锁；停止播放后释放。
收到开机完成广播后，在用户已开启监听时尝试恢复前台服务。

前台服务不能保证永不被杀。强行停止后须手动打开应用。厂商自启动、深度省电、
勿扰、通话、音量联动、音频路由和权限策略均可能影响效果。
悬浮窗可覆盖普通应用，但锁屏、安全页面和系统权限界面可能屏蔽，不能保证随时可见，
也不会绕过锁屏。未授权悬浮窗时退化为通知警告。
Android 新版可能限制验证码等敏感短信的广播，不能保证此类短信匹配。
RECEIVE_SMS 属受限权限，部分安装器/系统可能不允许授权；请在实际目标手机确认。
本版本用于直接安装测试，未进行 Google Play 短信权限和前台服务用途审核。

- https://developer.android.com/identity/providers/contacts-provider
- https://developer.android.com/reference/android/Manifest.permission
- https://developer.android.com/develop/background-work/services/fgs/service-types

## 构建

标准 Android Gradle 工程：用 Android Studio 打开本目录，安装 SDK 36，使用 JDK 17+。
AGP 8.12.0 需要 Gradle 8.13，可执行 `gradle :app:assembleDebug`，首次需要下载依赖。

当前 AOSP 工作区支持离线编译：

```sh
./scripts/build.sh
./scripts/test.sh
```

离线脚本使用上层 AOSP 目录中的 SDK 36、aapt2、R8、zipalign、apksigner，
也可通过 AOSP_ROOT 指定该目录。需要 javac、java、jar、keytool、zip。
测试另需 JVM org.json jar，默认从本机 Gradle 缓存找，可通过 JSON_JAR 指定。
调试签名密钥生成于 build/offline，不纳入 Git；请保留以便覆盖安装。
当前版本无预置音频文件，默认使用手机系统自带铃声。

## 0.2.2 logcat 诊断

业务日志同步到 logcat，统一标签 `AutoDroid`，应用内日志仍保留。
覆盖安装后打开应用，开启监听，执行以下命令后再发送真实短信：

```sh
adb logcat -v time -s AutoDroid:V AndroidRuntime:E
```

打开应用会输出 `APP_RESUME version=0.2.2`，可确认安装版本及短信权限。
启用监听应看到 `MONITOR_REQUEST`、`SERVICE_COMMAND` 和 `SERVICE_FOREGROUND`。
短信入口第一步打印 `SMS_RECEIVER_ENTER`，即使监听关闭也会打印。
后续 `SMS_PARSED`、`SMS_RULE_MATCH` 及匹配汇总区分解析、匹配和服务启动问题。
短信正文不输出，发送号码仅保留末四位；运行异常输出堆栈。
如果应用启动日志存在，但真实短信到达时没有入口日志，说明尚未观察到短信广播送达，
需要进一步检查系统权限、短信类型和系统广播分发，不能归因于号码匹配。

## 0.3.0 小米短信应用通知及最近任务

- 新增可选通知触发来源，仅监听 `com.android.mms`，可覆盖其发出的普通短信、RCS/5G 消息和小米网络消息通知。
- 每条宏可选择普通 SMS、应用通知或双来源；旧宏保持原来源，新建宏默认双来源。
- 优先提取 MessagingStyle 的最新一条消息及其发送人；普通通知读取标题和正文。姓名或号码需精确匹配，不从正文猜测发送人。
- 通知姓名是独立条件，与配置号码为“任意一个匹配”，同名联系人可能误匹配；应结合关键词。群聊暂不支持按群名匹配。
- 过滤汇总、常驻和监听开始前的历史通知，不主动重放已有通知。只取最新一条，批量合并通知可能遗漏较早消息。
- 同一通知的消息时间、发送人和正文未变化时，不重复执行。去重仅持久保存最近 128 个 SHA-256 指纹，不保存正文。
- 通知正文或发送人被隐藏、短信应用通知关闭、会话前台不发通知、附件无文字、系统屏蔽敏感通知时，无法保证触发。
- 若通知没有给出真实号码，请按通知实际显示的姓名填写，不自动把未知标题当成联系人。
- 主界面设置 excludeFromRecents，并在打开应用时排除已有任务；桌面图标、管理界面、前台服务通知仍可使用。
- 打开应用时恢复已开启但未运行的前台服务；从最近任务隐藏不代表系统后台保活。

升级后先打开应用，进入“权限与后台设置”授权通知访问；等待主页显示已连接，
编辑宏改为通知来源、配置姓名/号码和关键词并保存，然后开启监听，使用另一部手机发消息验证。
日志使用 `NOTIFICATION_CONNECTED`、`NOTIFICATION_RECEIVED`、`NOTIFICATION_PARSED` 和 `NOTIFICATION_SKIP` 标记。
请分别验证 SMS 和 RCS、应用前后台、锁屏、重复通知更新、停止警告以及最近任务列表。

## 0.3.1 双来源任一满足

编辑宏将来源设为“普通短信或应用通知（任一满足）”。同一条宏的号码/通知姓名、
关键词和动作共同使用，普通短信匹配成功或小米短信应用通知匹配成功都会立即执行，
无需等待另一来源。需同时授予接收短信权限和通知访问权限。

跨来源去重在宏服务内串行执行：同一宏在10秒内内容完全相同的两路事件配对后只执行一次，
同一来源连续收到的消息仍可分别执行。历史仅保存内容和规则指纹，不保存正文。
这是配对启发式：两路正文不同或延迟超过10秒时可能重复；同一宏包含多个联系人、
且不同联系人在10秒内从不同来源发来完全相同内容时，也可能被配对过滤。
手动测试不参与跨来源去重，原有普通短信/通知单来源宏保持原行为。

## 0.3.2 通知匹配诊断

`matchedRules=0` 表示没有匹配成功。新增 `NOTIFICATION_RULE index=... result=...`，
明确区分宏禁用、来源不符、发送人不符、关键词不命中或二者均不符。
`MATCH` 表示条件满足，后续服务日志说明执行状态；`NOTIFICATION_FIELDS` 记录提取路径和正文长度。
默认不输出发送人全名/完整号码或正文。如需核对通知实际发送人，可在“权限与后台设置”
开启“诊断：日志显示发送人姓名/号码”，此时 `NOTIFICATION_SENDERS` 和 `NOTIFICATION_CONFIG`
会记录实际发送人与配置值，正文仍不输出。排查完成后关闭该开关，可清空应用日志。

## 0.3.3 过滤运行提示

除常驻/汇总通知外，明确过滤 FLAG_FOREGROUND_SERVICE 或小米 Channel_Foreground_Service
通道的运行通知（例如“短信正在运行”），日志标明这不是联系人消息。
此过滤仅减少误判和诊断噪声，不保证系统已向监听器投递真实消息通知。
测试时退出短信会话并回桌面，再由另一部手机发消息，确认系统生成联系人消息通知。

## 0.3.4 通知字段诊断

在“权限与后台设置”开启“诊断：通知字段名称与类型”，查看 NOTIFICATION_DUMP_BEGIN、
NOTIFICATION_DUMP_META、NOTIFICATION_FIELD、NOTIFICATION_DUMP_END。
输出通知ID、通道、标志位、类别、可见性、时间、自定义布局/点击意图是否存在，
递归检查 extras、publicVersion.extras、消息 Bundle 数组及 Person 姓名/URI。
诊断在通知过滤前执行，运行提示、汇总通知也能检查；仍仅处理 com.android.mms，且需开启监听。

默认只显示字段名称/类型/长度。若需要具体值，单独开启“输出通知字段值”，
此选项会同时启用字段诊断，日志可能包含正文、联系人姓名及号码；排查后关闭并清空应用日志。
字段值也会写入系统logcat；清空应用日志不会清除已经导出的系统日志。
为限制日志量，每个通知最多80行、递归4层、每个数组或Bundle最多16项、文本最多256字符；
不执行 PendingIntent、不解码私有对象、不展开字节数组。自定义布局存在不代表能获取其内部文本。
已通过编译和签名校验；字段诊断效果需在目标手机实际通知上验证。

## 0.3.5 隐藏并停用网络消息通知触发

隐藏通知访问、字段诊断、通知姓名及来源选择入口；通知服务组件 enabled=false，
并忽略升级过程残留的通知回调。保留普通 SMS、多号码/通讯录选择、手动测试及最近任务隐藏。
旧宏的号码、关键词和动作保留，无号码的通知宏禁用。旧日志保留，可在执行日志中手动清空。

## 0.3.6 执行时的重要通知

每次实际执行宏（包括手动测试），在弹窗和播放前发送“重要警告 · 宏名称”通知，
内容为宏配置的警告文字，提供“确认并停止”按钮。使用 alerts 重要宏警告通道，
默认 IMPORTANCE_HIGH、CATEGORY_ALARM，锁屏使用私密可见性（实际展示由系统设置决定）。
声音超时、失去焦点或播放错误停止时保留通知；确认警告或关闭监听会清除通知。
多条宏仍由最后一条接管警告和通知，不保留逐条执行历史通知。

在“权限与后台设置”授予 Android 13+ 通知权限，并打开“重要警告通知设置”，
按需允许横幅、声音和锁屏显示。既有通道的重要性不会被强制覆盖，不绕过勿扰。
日志 IMPORTANT_NOTIFY_POSTED 记录提交及实际通道重要性，BLOCKED/FAILED/HINT 记录权限或设置问题；
POSTED 不代表系统一定展示横幅。小米还可能要求打开悬浮通知/锁屏通知。
本次仅完成离线构建、签名和既有规则检查；通知展示、确认按钮及超时保留需真机验证。

## 0.3.7 宏导出和恢复

主页“导出宏备份”通过系统文件选择器生成 AutoDroid-macros-日期时间.json；
请保存到下载目录、外部存储或你选择的云盘等应用私有目录之外，并确认文件存在后再卸载。
导出规则包含名称、号码、关键词、通道、音量、音源地址、警告文字、播放时长和启用状态。
备份是未加密的JSON，包含联系人号码和宏内容，请妥善保管，不包含签名、系统授权或执行日志。

“导入宏备份”选择JSON后显示宏数量，可追加或替换。替换需二次确认，重复追加会产生重复宏。
整份文件校验通过才允许保存；无效文件不修改现有配置。导入完成关闭监听、停止当前警告，
检查规则后手动开启。支持当前版本备份及旧版规则JSON数组，来源统一转换为普通短信。
最多1MB、500条宏、每条100个号码；不支持的格式、类型、数值范围和音源协议会拒绝。
音频文件不打包进备份；卸载重装或换手机后须重新选择本地音源并授予通知、短信、悬浮窗权限。

签名不匹配时无法用新版覆盖旧版，因此无法靠安装本功能直接读取旧版本私有数据。
需找回原签名后编译可覆盖的版本，或先手动记录旧宏；不要在未保存配置前直接卸载。
当前构建和签名校验通过，75项消息匹配与21项备份检查通过；文件选择器与恢复操作需真机验证。

## 0.3.8 读取最近消息诊断

主页点击“读取最近消息诊断”，按需申请 READ_SMS，然后只读查询 content://sms/inbox，
展示按时间倒序最近20条消息的ID、类型、号码、时间及正文（每条最多展示512字符）。
可用“重新读取”检查刚到达的测试消息；结果仅在页面内存中展示，不写入备份、执行日志或logcat。
执行日志仅记录读取数量/错误类型，不注册ContentObserver、不自动扫描、不执行宏、不修改已读状态。
READ_SMS 是独立权限，已有 RECEIVE_SMS 不代表能读取。授权失败时显示错误和应用权限入口。
如果RCS不出现在标准短信表，可能存于独立Provider或被系统过滤，当前诊断不访问厂商私有Provider。
空列表不一定表示数据库为空，也可能是系统过滤；诊断需要真机授权和查询验证。

## 0.4.0 收件箱自动触发与禁用联网

- 开启监听需授予READ_SMS，前台服务在工作线程注册 content://sms 和 content://mms-sms 的 ContentObserver，变化后查询 content://sms/inbox。
- 按 _id 递增处理、每批最多100条，只匹配 date 不早于本次监听起点的记录；首次升级启用数据库触发时建立新起点，忽略升级前记录。
- ID处理进度持久保存，重复变化/标记已读不会重复报警；服务重启时可补处理原监听起点之后尚未处理的记录。关闭后重新开启会建立新的时间窗口。
- 新消息按现有号码和关键词匹配，再执行音量、音源、弹窗及重要通知。日志只输出ID、type、脱敏号码和命中数量，不输出正文。
- 有读取权限时SMS广播只唤醒同一数据库查询，不直接执行动作，避免广播和Observer双重报警。无读取权限时旧广播路径仍可用，但无法读取数据库RCS。
- 关闭监听或服务销毁会注销Observer。首次建立基线日志为 INBOX_BASELINE_INITIALIZED，注册与查询成功为 INBOX_OBSERVER_REGISTERED / INBOX_OBSERVER_READY，消息为 INBOX_MESSAGE。
- ID假定是该收件箱Provider内的稳定递增主键；Provider重建/ID重置时可关闭并重新开启监听。云端历史同步用原消息时间过滤；若同步记录被赋予当前时间，可能仍被视为新消息。
- 进度先保存再派发动作，避免进程崩溃后重复报警；保存后、动作执行前若进程退出，可能漏执行该次，不能保证故障下恰好一次。

最终APK不声明INTERNET、ACCESS_NETWORK_STATE、ACCESS_WIFI_STATE等网络权限；无HTTP/Socket客户端。
同时 usesCleartextTraffic=false，播放仅接受 content/file/android.resource 本地URI，禁止HTTP等网络音源。
系统短信应用本身接收RCS仍可能联网，本应用的网络禁用不影响其他应用。用户主动选择系统文件提供者时，其云端行为由该提供者管理。
测试包括75项匹配、21项备份及15项ID进度/历史过滤检查；Observer实际投递和后台行为还需手机验证。
