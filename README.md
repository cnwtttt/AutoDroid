# AutoDroid 0.3.2

普通手机短信与小米短信应用通知警告自动化应用，Android 8.0（API 26）以上，无需 root。

## 使用

1. 安装 `build/offline/AutoDroid-debug.apk`。
2. 打开“权限与后台设置”，授权所用来源：普通短信需要接收短信权限，通知来源需要“短信应用通知访问”。另授权通知、悬浮窗，按需授予勿扰访问。
3. 在系统电池设置中允许不受限制的后台运行；部分品牌还需允许自启动。
4. 新建短信宏：手动填写多个发送号码，或点击“从通讯录选择多个联系人/号码”，授权后搜索姓名或号码并多选。联系人有多个号码时分别勾选，重复号码自动合并。
5. 选择触发来源：普通 SMS 广播，或“小米短信应用通知（SMS / RCS / 网络消息）”。通知模式还应核对“通知显示的联系人姓名”，从通讯录选择时会自动填入；老规则需重新选择联系人或手动填姓名。然后设置关键词、音量通道、音源及弹窗。
6. 保存后点击“手动测试”，确认音量、声音和弹窗。手动测试跳过短信匹配和启用状态。
7. 开启后台短信监听，用另一部手机发短信验证。常驻通知可停止声音、关闭监听。

音源可选系统铃声或通过系统文件选择器选择本地音频，默认系统闹钟铃声。
音量支持闹钟、媒体、铃声、通知；设置百分比转换为设备实际档位，播放使用同一通道。
声音循环播放，点击确认或达到时限（5～600 秒）停止。音量不自动恢复。
规则、启用状态和日志保存于应用私有目录，重启后保留。短信和音频不上传，无网络权限。

## 匹配与执行

- 一条宏支持多个发送号码，任意一个匹配即可触发，支持换行、中英文逗号/分号分隔；
- 完整发送号码匹配；统一全角/半角及数字格式，去除空白、不可见方向字符、括号和连字符，兼容中国 `+86` 和 `0086` 前缀。
- 通讯录列表支持姓名/号码搜索及多选；可混合使用手填号码和联系人号码。
- 保存的是选中时的号码，不随通讯录后续修改自动同步；选择结果在保存宏后生效。
- 兼容旧版单号码规则，编辑保存后使用多号码格式。
- 关键词区分大小写，留空匹配所选号码所有短信；分段短信合并匹配。
- 多条规则命中按列表顺序执行，最后一条接管声音和弹窗；日志记录每次执行。
- 日志包含宏名称、收到短信的脱敏号码及未命中原因，不保存短信正文或完整号码。日志最多约 16000 字符。
- 新警告替换当前警告，不进行排队。关闭监听同时停止当前警告。

## 权限和系统限制

接收短信使用运行时 RECEIVE_SMS 权限，不读取历史短信，不发送短信。
通讯录 READ_CONTACTS 权限仅在使用联系人选择时申请；拒绝后仍可手动输入号码。
只读取联系人姓名和号码供选择，不上传通讯录、不修改联系人。
通知来源需在系统设置中授予 NotificationListenerService 通知访问权限，与发送通知权限不同。
系统授权覆盖通知访问能力，代码只处理 com.android.mms 的消息通知，不上传、不保存正文。
Android 13+ 申请通知权限。悬浮窗和勿扰访问需在系统设置中明确授权。
以前台 specialUse 服务执行用户开启的短信自动化，播放时增加 mediaPlayback 类型。
播放期间使用音频焦点及局部唤醒锁；停止播放后释放。
收到开机完成广播后，在用户已开启监听时尝试恢复前台服务。

前台服务不能保证永不被杀。强行停止后须手动打开应用。厂商自启动、深度省电、
勿扰、通话、音量联动、音频路由和权限策略均可能影响效果。
悬浮窗可覆盖普通应用，但锁屏、安全页面和系统权限界面可能屏蔽，不能保证随时可见，
也不会绕过锁屏。未授权悬浮窗时退化为通知警告。
Android 新版可能限制验证码等敏感短信的广播，不能保证此类短信匹配。
RECEIVE_SMS 属受限权限，部分安装器/系统可能不允许授权；请在实际目标手机确认。
本版本用于直接安装测试，未进行 Google Play 短信权限和前台服务用途审核。

官方参考：
- https://developer.android.com/identity/providers/contacts-provider
- https://developer.android.com/reference/android/Manifest.permission
- https://developer.android.com/develop/background-work/services/fgs/service-types

## 构建

标准 Android Gradle 工程：用 Android Studio 打开本目录，安装 SDK 36，使用 JDK 17+。
AGP 8.12.0 需要 Gradle 8.13，可执行 `gradle :app:assembleDebug`，首次需要下载依赖。

当前 AOSP 工作区支持离线编译：

```sh
./scripts/build.sh
./scripts/test.sh
```

离线脚本使用上层 AOSP 目录中的 SDK 36、aapt2、R8、zipalign、apksigner，
也可通过 AOSP_ROOT 指定该目录。需要 javac、java、jar、keytool、zip。
测试另需 JVM org.json jar，默认从本机 Gradle 缓存找，可通过 JSON_JAR 指定。
调试签名密钥生成于 build/offline，不纳入 Git；请保留以便覆盖安装。
当前版本无预置音频文件，默认使用手机系统自带铃声。

## 验证范围

源码编译、DEX 转换、APK 打包与签名校验；71 项消息匹配单元检查覆盖多号码任意匹配、分隔符、去重、旧规则兼容、持久化、前缀、关键词、
禁用规则、服务号码、空号码和错误号码，以及通知姓名/号码匹配、来源隔离和重复通知过滤。
普通 SMS 流程已由用户真机日志确认匹配、音量设置和播放；新增通知流程及最近任务行为尚未真机验证。

真机需检查：通讯录授权/拒绝、联系人搜索/多选/取消、多号码短信匹配、旧规则升级、手动测试、真实长短信、非匹配号码、后台/锁屏、
音频文件重启后访问、停止/超时、服务重启、开机恢复和强行停止后的恢复。

## 0.2.1 短信匹配修复

修复号码中含不可见字符、不间断空格、全角加号/数字及 Unicode 连字符时，
`+86` 前缀未正确处理的问题。保存的号码和收到的号码使用相同的标准化逻辑，旧规则无需重建。
新日志能区分号码不匹配、关键词不命中和没有启用宏。
若监听已开启但日志中没有“收到短信”，需检查短信权限、系统广播限制及后台运行状态。
目前只完成离线编译与匹配检查，尚未在用户手机复现或验证。

## 0.2.2 logcat 诊断

业务日志同步到 logcat，统一标签 `AutoDroid`，应用内日志仍保留。
覆盖安装后打开应用，开启监听，执行以下命令后再发送真实短信：

```sh
adb logcat -v time -s AutoDroid:V AndroidRuntime:E
```

打开应用会输出 `APP_RESUME version=0.2.2`，可确认安装版本及短信权限。
启用监听应看到 `MONITOR_REQUEST`、`SERVICE_COMMAND` 和 `SERVICE_FOREGROUND`。
短信入口第一步打印 `SMS_RECEIVER_ENTER`，即使监听关闭也会打印。
后续 `SMS_PARSED`、`SMS_RULE_MATCH` 及匹配汇总区分解析、匹配和服务启动问题。
短信正文不输出，发送号码仅保留末四位；运行异常输出堆栈。
如果应用启动日志存在，但真实短信到达时没有入口日志，说明尚未观察到短信广播送达，
需要进一步检查系统权限、短信类型和系统广播分发，不能归因于号码匹配。

## 0.3.0 小米短信应用通知及最近任务

- 新增可选通知触发来源，仅监听 `com.android.mms`，可覆盖其发出的普通短信、RCS/5G 消息和小米网络消息通知。
- 每条宏可选择普通 SMS、应用通知或双来源；旧宏保持原来源，新建宏默认双来源。
- 优先提取 MessagingStyle 的最新一条消息及其发送人；普通通知读取标题和正文。姓名或号码需精确匹配，不从正文猜测发送人。
- 通知姓名是独立条件，与配置号码为“任意一个匹配”，同名联系人可能误匹配；应结合关键词。群聊暂不支持按群名匹配。
- 过滤汇总、常驻和监听开始前的历史通知，不主动重放已有通知。只取最新一条，批量合并通知可能遗漏较早消息。
- 同一通知的消息时间、发送人和正文未变化时，不重复执行。去重仅持久保存最近 128 个 SHA-256 指纹，不保存正文。
- 通知正文或发送人被隐藏、短信应用通知关闭、会话前台不发通知、附件无文字、系统屏蔽敏感通知时，无法保证触发。
- 若通知没有给出真实号码，请按通知实际显示的姓名填写，不自动把未知标题当成联系人。
- 主界面设置 excludeFromRecents，并在打开应用时排除已有任务；桌面图标、管理界面、前台服务通知仍可使用。
- 打开应用时恢复已开启但未运行的前台服务；从最近任务隐藏不代表系统后台保活。

升级后先打开应用，进入“权限与后台设置”授权通知访问；等待主页显示已连接，
编辑宏改为通知来源、配置姓名/号码和关键词并保存，然后开启监听，使用另一部手机发消息验证。
日志使用 `NOTIFICATION_CONNECTED`、`NOTIFICATION_RECEIVED`、`NOTIFICATION_PARSED` 和 `NOTIFICATION_SKIP` 标记。
请分别验证 SMS 和 RCS、应用前后台、锁屏、重复通知更新、停止警告以及最近任务列表。

官方参考：
- https://developer.android.com/reference/android/service/notification/NotificationListenerService
- https://developer.android.com/guide/topics/manifest/activity-element

## 0.3.1 双来源任一满足

编辑宏将来源设为“普通短信或应用通知（任一满足）”。同一条宏的号码/通知姓名、
关键词和动作共同使用，普通短信匹配成功或小米短信应用通知匹配成功都会立即执行，
无需等待另一来源。需同时授予接收短信权限和通知访问权限。

跨来源去重在宏服务内串行执行：同一宏在10秒内内容完全相同的两路事件配对后只执行一次，
同一来源连续收到的消息仍可分别执行。历史仅保存内容和规则指纹，不保存正文。
这是配对启发式：两路正文不同或延迟超过10秒时可能重复；同一宏包含多个联系人、
且不同联系人在10秒内从不同来源发来完全相同内容时，也可能被配对过滤。
手动测试不参与跨来源去重，原有普通短信/通知单来源宏保持原行为。

## 0.3.2 通知匹配诊断

`matchedRules=0` 表示没有匹配成功。新增 `NOTIFICATION_RULE index=... result=...`，
明确区分宏禁用、来源不符、发送人不符、关键词不命中或二者均不符。
`MATCH` 表示条件满足，后续服务日志说明执行状态；`NOTIFICATION_FIELDS` 记录提取路径和正文长度。
默认不输出发送人全名/完整号码或正文。如需核对通知实际发送人，可在“权限与后台设置”
开启“诊断：日志显示发送人姓名/号码”，此时 `NOTIFICATION_SENDERS` 和 `NOTIFICATION_CONFIG`
会记录实际发送人与配置值，正文仍不输出。排查完成后关闭该开关，可清空应用日志。
