# AutoDroid 0.1

普通手机短信警告自动化应用，Android 8.0（API 26）以上，无需 root。

## 使用

1. 安装 `build/offline/AutoDroid-debug.apk`。
2. 打开“权限与后台设置”，授权接收短信、通知、悬浮窗；按需授予勿扰访问。
3. 在系统电池设置中允许不受限制的后台运行；部分品牌还需允许自启动。
4. 新建短信宏：填发送号码、可选关键词、音频通道、音量、音源、弹窗内容、最长播放时间。
5. 保存后点击“手动测试”，确认音量、声音和弹窗。手动测试跳过短信匹配和启用状态。
6. 开启后台短信监听，用另一部手机发短信验证。常驻通知可停止声音、关闭监听。

音源可选系统铃声或通过系统文件选择器选择本地音频，默认系统闹钟铃声。
音量支持闹钟、媒体、铃声、通知；设置百分比转换为设备实际档位，播放使用同一通道。
声音循环播放，点击确认或达到时限（5～600 秒）停止。音量不自动恢复。
规则、启用状态和日志保存于应用私有目录，重启后保留。短信和音频不上传，无网络权限。

## 匹配与执行

- 完整发送号码匹配；去除空格、括号、连字符，兼容中国 `+86` 和 `0086` 前缀。
- 联系人通过其号码指定；暂不读取通讯录，不支持按姓名选择。
- 关键词区分大小写，留空匹配该号码所有短信；分段短信合并匹配。
- 多条规则命中按列表顺序执行，最后一条接管声音和弹窗；日志记录每次执行。
- 日志包含宏名称和结果，不保存短信正文。日志最多约 16000 字符。
- 新警告替换当前警告，不进行排队。关闭监听同时停止当前警告。

## 权限和系统限制

接收短信使用运行时 RECEIVE_SMS 权限，不读取历史短信，不发送短信。
Android 13+ 申请通知权限。悬浮窗和勿扰访问需在系统设置中明确授权。
以前台 specialUse 服务执行用户开启的短信自动化，播放时增加 mediaPlayback 类型。
播放期间使用音频焦点及局部唤醒锁；停止播放后释放。
收到开机完成广播后，在用户已开启监听时尝试恢复前台服务。

前台服务不能保证永不被杀。强行停止后须手动打开应用。厂商自启动、深度省电、
勿扰、通话、音量联动、音频路由和权限策略均可能影响效果。
悬浮窗可覆盖普通应用，但锁屏、安全页面和系统权限界面可能屏蔽，不能保证随时可见，
也不会绕过锁屏。未授权悬浮窗时退化为通知警告。
Android 新版可能限制验证码等敏感短信的广播，不能保证此类短信匹配。
RECEIVE_SMS 属受限权限，部分安装器/系统可能不允许授权；请在实际目标手机确认。
本版本用于直接安装测试，未进行 Google Play 短信权限和前台服务用途审核。

官方参考：
- https://developer.android.com/reference/android/Manifest.permission
- https://developer.android.com/develop/background-work/services/fgs/service-types

## 构建

标准 Android Gradle 工程：用 Android Studio 打开本目录，安装 SDK 36，使用 JDK 17+。
AGP 8.12.0 需要 Gradle 8.13，可执行 `gradle :app:assembleDebug`，首次需要下载依赖。

当前 AOSP 工作区支持离线编译：

```sh
./scripts/build.sh
./scripts/test.sh
```

离线脚本使用上层 AOSP 目录中的 SDK 36、aapt2、R8、zipalign、apksigner，
也可通过 AOSP_ROOT 指定该目录。需要 javac、java、jar、keytool、zip。
测试另需 JVM org.json jar，默认从本机 Gradle 缓存找，可通过 JSON_JAR 指定。
调试签名密钥生成于 build/offline，不纳入 Git；请保留以便覆盖安装。
当前版本无预置音频文件，默认使用手机系统自带铃声。

## 验证范围

源码编译、DEX 转换、APK 打包与签名校验；号码匹配单元检查覆盖前缀、关键词、
禁用规则、服务号码、空号码和错误号码。尚未完成真机端到端验证。

真机需检查：授权/拒绝、手动测试、真实长短信、非匹配号码、后台/锁屏、
音频文件重启后访问、停止/超时、服务重启、开机恢复和强行停止后的恢复。
